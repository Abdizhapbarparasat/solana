# Неделя 10: RPC, API и blockchain data

**Задание:** создать dashboard с балансами, токенами, транзакциями и активностью программ.

## Что сделано

Блок **Dashboard** в web-клиенте (`web/src/Dashboard.tsx`), данные берутся из RPC
(`web/src/lib/chain.ts`). Обновляется каждые 30 секунд и по кнопке Refresh.

| Раздел | Что показывает | RPC-метод |
|---|---|---|
| Balances | Баланс SOL | `getBalance` |
| Balances | SPL-токены кошелька (Token и Token-2022) | `getParsedTokenAccountsByOwner` |
| My latest transactions | 10 последних транзакций кошелька со статусом и ссылкой на Explorer | `getSignaturesForAddress` |
| Program activity | 20 последних транзакций программы `tip_jar` и доля успешных | `getSignaturesForAddress` |

Раздел Program activity работает и без подключённого кошелька.

## Как это работает (для отчёта)

- **RPC** (Remote Procedure Call): клиент отправляет JSON-запрос узлу Solana и получает
  данные аккаунтов и транзакций. Публичный endpoint devnet ограничивает частоту запросов,
  поэтому для серьёзной нагрузки берут провайдера (Helius, QuickNode) и вписывают его адрес
  в `VITE_RPC_URL` в `web/.env`.
- Токен-аккаунт хранит баланс отдельно от кошелька: у каждого токена свой token account,
  поэтому список токенов получают отдельным методом.
- `getSignaturesForAddress` возвращает подписи транзакций, где адрес участвовал, от новых
  к старым. Поле `err` равно `null`, если транзакция успешна.

## Как проверить

```bash
cd web
npm install
npm run dev
```
Подключи кошелёк, в блоке Dashboard должны появиться баланс SOL, токены (если есть) и
транзакции. Чтобы появились токены, запусти скрипт `mint-token.ts` из недели 7 тем же кошельком.
