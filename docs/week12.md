Vault хранит SOL одного владельца (authority). Забрать SOL должен мочь только он.

## Уязвимость: missing signer check

**Где:** структура `Withdraw` в `vuln_vault`.

```rust
/// CHECK: INTENTIONALLY VULNERABLE
pub authority: UncheckedAccount<'info>,   // не Signer!
```

Инструкция `withdraw` сравнивает публичный ключ `authority` с ключом, сохранённым в vault:

```rust
require_keys_eq!(vault.authority, authority.key(), ...);
```

Это выглядит как проверка доступа, но сравнение ключей **не доказывает, что владелец
одобрил транзакцию**. Публичный ключ любого человека известен всем. Подпись проверяется
только если аккаунт объявлен как `Signer`.

Дополнительно получатель (`recipient`) выбирается вызывающим, поэтому деньги можно
отправить на любой адрес.

## Exploit (шаги атаки)

1. Найти vault жертвы: его адрес выводится из публичного ключа жертвы (`["vault", authority]`).
2. Собрать инструкцию `withdraw`: в `authority` подставить **публичный ключ жертвы**
   (без подписи), в `recipient` поставить свой адрес.
3. Отправить транзакцию. Подписывает её только атакующий (как плательщик комиссии).
4. Программа сравнивает ключи, они совпадают, и SOL уходят атакующему.

Результат в тесте: баланс атакующего вырос ровно на украденную сумму
(тест `EXPLOIT` в `tests/security_lab.ts`).

**Влияние:** критическое. Любой может опустошить любой vault. Затраты атакующего: комиссия.

## Исправление

В `secure_vault`:

```rust
#[account(
    mut,
    seeds = [b"vault", authority.key().as_ref()],
    bump = vault.bump,
    has_one = authority        // vault.authority должен совпасть
)]
pub vault: Account<'info, Vault>,
#[account(mut)]
pub authority: Signer<'info>,  // FIX: подпись обязательна
```

И SOL теперь уходят только самому authority (поле `recipient` убрано).

Результат в тестах: атака без подписи отклоняется, а настоящий владелец
со своей подписью выводит средства.

## Чек-лист проверки программ Solana

| Проверка | Что может пойти не так |
|---|---|
| Signer check | Нет подписи, как в этой лабораторной |
| Owner check | Аккаунт принадлежит чужой программе, данные подделаны |
| Account validation | Подставлен чужой аккаунт вместо ожидаемого PDA |
| Арифметика | Переполнение (`checked_add`, `overflow-checks = true`) |
| Arbitrary CPI | Вызов произвольной программы вместо проверенной |
| Rent и закрытие аккаунтов | Закрытый аккаунт можно «оживить», вывод ниже rent-резерва |
